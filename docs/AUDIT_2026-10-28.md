# Audit of 2026-10-28: findings, recommendations and open questions

A full code audit and bug search of the package as of commit 0718b26 (seven code reviewers, one
per module group, each reading every line of its scope; the engine's numerics checked against
direct NumPy and SciPy computations). Every finding marked CONFIRMED was reproduced a second time,
independently of the reviewer, from the reviewer's script or by a direct probe; PLAUSIBLE ones were
verified by reading the code only. Nothing in the repository was changed. Decisions are left to the
owner; the layout follows docs/AUDIT_2026-10-17.md so that the decisions can be recorded beside
each item.

Baseline: 1,127 tests pass, 21 skipped (data and GPU), ruff clean, CI green through 630eda0
(0718b26 was still running). No Critical finding. The numerical core (binomial pmf and its
normalisation, recurrence, convolution, float32 gradients, k-means starts with the mean kept,
per-bin weight units across fit, polish, screen floor, bootstrap and null, bootstrap matching,
CPU parity) was verified correct. The previous audit's items were checked and none regressed.

Severity: High = wrong results, data mix-up or a crash in a realistic path; Medium = wrong in an
edge case, misleading output or a design inconsistency with a real effect; Low = cosmetic,
message wording, latent hazards.

## High

1. **`best_set_K` evidence counts spectra the analysis left out** (`analysis/species.py:1094-1121`,
   `_set_evidence`, called at `:1077`). The set's criterion sums run over `_kept & fitted &
   finite` only; the whole-spectrum filters of `_left_out` (quality screens "remove", stand-in
   control, above the amide count, replicate outlier) and the screens' "one population only"
   action are never applied, although the species rows exclude those spectra (`_spectrum_records`
   `keep &= ~out`, `usable &= ~one`). A removed spectrum with a large K = 2 gain still votes the
   set to two; a spectrum kept "at K = 1 only" still votes with its K = 2 criterion. This is the
   default rule for every bundle without `[run.population_test]`. CONFIRMED (synthetic run: a
   spectrum listed in left_out_spectra, set n_spectra 14 in the table, evidence n 15). The
   population-test path (`set_test._run_rows`) applies the filters correctly.
   *Fix:* have `_spectrum_records` return the per-spectrum, per-K usable masks it used and sum
   the criterion over exactly those rows (pass `filters` and `controls` through
   `species_uptake`); a set whose K = 2 spectra are all "one population only" reads one. Test:
   a spectrum left out whole must not change `set_delta_criterion`.
   *Decision (owner, 2026-10-29):* fix as recommended, with the test.
2. **Promoted control roles are stored with the raw spectra and survive a rerun from the stored
   spectra** (`run.py:732-733`: `with_control_roles` is applied before `stored = data`;
   `io/_arrow.py:105`, `io/bundle.py:1343`, `config.py:1109-1124`). A run with
   `[run.controls] fulldeut_at = "60 s"` writes `fulldeut` roles into the bundle's spectra; a
   rerun with `[input] spectra = <bundle>` and the setting removed or changed still averages the
   60 s spectra into the FD control, drops them from the time course, the replicate-variance pool
   and every per-role grouping. CONFIRMED (n_fd 5 instead of 2; the 60 s point absent).
   *Fix:* store the readers' roles (take `stored` before `with_control_roles`, or strip the
   promoted roles on write); the promotion is re-applied from the project file on every run.
   Test: run with `fulldeut_at`, reload with `load_stored_spectra`, roles equal the input's.
   *Decision:* store the readers' roles only; the promotion is re-applied from the project
   file on every run. (Spectra files written before roles existed load with empty roles;
   `undeut_at`/`fulldeut_at` is the recovery, to be said in the guide.)
3. **A carried-over review choosing a K the new run's screen skipped crashes at write time
   instead of being marked stale** (`io/bundle.py:996-1002` `mark_stale` tests only
   `k not in fit.k_values`, not `fit.fitted(k)[i]`; `run.py:912-923`; `_check_review`
   `:1062-1072` then raises through `effective_K`). With a bootstrap the failure is at the
   checkpoint write (`run.py:870`), after all fitting; the previous bundle survives. Realistic:
   `--overwrite` with `[run.fit] screen = true` (the recommended speed setting) or with the
   population test's screen on. CONFIRMED. `_missing_choices` (`run.py:603`) handles the same
   case correctly, so the two places disagree; the 2026-10-17 contract ("override ignored while
   stale") is not met.
   *Fix:* in `mark_stale`, also mark stale when `k != 0 and not fit.fitted(k)[index[sid]]`; keep
   `_check_review`. Same check for `[review] table` choices at report time (see Medium 5).
   *Decision:* fix as recommended, with a test.
4. **Duplicate spectrum ids from a folder-format peptide table** (`io/read.py:415-455`,
   `io/specexport.py:344`, `io/hxexpress.py:178`). The local id is the file location only, so
   two table rows reading the same file and charge (a row listed twice, or one peptide folder
   with two `modification` values, which pyHXExpress's table allows) give two series with
   identical ids; only the scan formats check uniqueness (`io/mzml.py:1156`). Everything keyed
   by id (review table, `[[input.exclude]]`, `[[review.exclude]]`, `SpectrumSet.find`, the
   bundle's id dicts and set-based checks) then applies to the wrong twin or the first only.
   CONFIRMED (10 spectra, 5 distinct ids, data_id 0 and 1).
   *Fix:* refuse repeated ids in `read_spectra`/`_read` with the entries named (as
   `_check_unique_ids` does), or make the local id carry the entry (modification or data_id)
   when a file is shared; `spectrum_index` must mirror the choice.
   *Decision:* the owner needs different modifications of one peptide file to be read as
   separate series, so no refusal: the id carries the modification (or data_id) only when one
   file is shared by several table entries, so every existing id stays the same.
5. **Name-only run records collapse runs whose files share a name** (`io/mzml.py:1061-1069`
   `_run_paths`, `:1639-1650` `_repeat_read`). With `record_paths = "name"` or any repeat read
   with `directory=`, two runs `A/rep1.mzML` (sample A) and `B/rep1.mzML` (sample B) are recorded
   as one name; the repeat opens one file for both, `compare_identity` only warns under the
   default `on_change = "warn"`, and sample B gets sample A's spectra. CONFIRMED (both weighted
   m/z 625.92 after the repeat; one WARNING line).
   *Fix:* refuse `record_paths = "name"` when two runs record the same name; refuse a repeat read
   in which two runs resolve to one path.
   *Decision:* fix as recommended, with a test.
6. **Fragment-ion series with intrinsic rates enter the theoretical back-exchange fit as fully

   `uncorrected;fd_off_model;fd_kint`, mfd 8.0 instead of 10.0).
   *Fix:* at the top of `fit_controls`, drop the uncorrected ids from `rates`; test with one

   *Decision:* fix as recommended, with the test.
7. **uptake.csv is empty for every uncorrected series when the run has controls**

8. **`[figures] corrected = true` crashes on an uncorrected series** (`report/series.py:348-357`

   *Fix:* `use = corrected and row is not None`, drawing the series uncorrected; test.

9. **`load_results` on a zip bundle hands back a loader on a closed archive** (`report/notebook.py:36-45`:

## Medium

### Settings and command line
1. **`[output]` booleans accept strings and coerce with `bool()`** (`config.py:669-676`):
   `overwrite = "false"` means true (an existing bundle is silently replaced), `keep_spectra =
   "no"` stores the spectra, `tables = "true"` writes into a folder named `true`. Every other
   table goes through `_check_types`; `[output]` does not (`[input] parents = "yes"` likewise,
   `:638`). CONFIRMED. *Fix:* `_check_types(data, OutputSettings, "output")`.
2. **`hxex report --keep-previous` and `hxex analyse --keep-previous` move the output folder
   before the bundle is opened and before their own refusals** (`cli.py:789-793`, `:1118-1119`).
   A refused command (review K without a bootstrap, a mistyped bundle path, a wrong
   `--reference`) leaves a stray `NAME.N` generation and no output. `cmd_run` does it right
   (check with `move=False`, move after the run). CONFIRMED. *Fix:* the `cmd_run` pattern in
   both commands.
3. **A project file saved with a UTF-8 BOM is refused as "not valid TOML (Invalid statement (at
   line 1, column 1))"** (`config.py:932`, `encoding="utf-8"`); every other user file is read
   with `utf-8-sig`. CONFIRMED. *Fix:* `utf-8-sig`.
4. **`hxex report hxex.toml` ignores `[output] tables = DIR`** and writes `<bundle>_tables`
   (`cli.py:785-788`), a second divergent copy, while `hxex check` describes the explicit folder
   as one report touches. `cmd_resume` reads it (`:737`). CONFIRMED by trace. *Fix:* default
   `args.tables` from `project.output.tables` as resume does.
5. **A review table choosing a K the run never fits (`review_K > k_max`) is reported only after
   the whole run** (`cli.py:654` → `run._missing_choices` `:603` skips it silently;
   `apply_review_table` raises at `:667` when the tables are written; `hxex resume` then says
   "nothing to add"). CONFIRMED by trace. *Fix:* validate against `k_max` in `hxex check`
   (`_review_table_line`) and in `cmd_run` before the read; the same for a K the screen
   skipped (High 3).

### Readers
6. **The mzML reader ignores `referenceableParamGroupRef`** (`io/mzml.py:185-188` `_cv` reads
   direct `cvParam`s only; used for ms level, centroid/profile, scan time, precursor and
   binary-array encoding). mzML 1.1 allows a spectrum's parameters by reference, and the PSI
   example files put `ms level` there: such a file reads every scan as MS1 with centroiding
   "not stated" (then summed as profile). CONFIRMED on a synthetic file; ThermoRawFileParser and
   msconvert write direct params, so frequency on real input is unknown. *Fix:* parse
   `referenceableParamGroupList` once per file and merge the referenced params in `_cv`; at
   least raise when a spectrum has a ref and no `ms level`.

### Picking and screens
7. **The m/z check never assesses centroided spectra** (`picking/recentre.py:55-80` `_peak_top`).
   The climb step is 1.6 times the local point spacing, which in centroided data is the isotope
   spacing, so the climb crosses to a taller isotope stick and the parabola runs through three
   sticks (apex +52 ppm). `envelope_offset` then needs two agreeing peaks and gets NaN: no
   `off_mz` flag, no recentring, no warning on centroided mzML or raw scans, contrary to the
   module docstring. CONFIRMED. *Fix:* detect centroided data as `pick._peaks` does and return
   the nearest stick without climb or parabola; bound the profile climb by the spectrum's
   median spacing. Add a centroided case to tests/test_recentre.py.
8. **`screen_below_mono` under-reads for peptides whose monoisotopic cluster is not the tallest**
   (`picking/screen.py:139` with `:76`): the contaminant's envelope is extrapolated with the
   shape normalised to its tallest cluster instead of to M. CONFIRMED with a same-shape
   contaminant at half height: 10 residues 0.199 (true 0.201), 25 residues 0.165 (true 0.286),
   41 residues 0.062 (true 0.318): the agreed loose threshold (0.10) misses a 32 % contaminant
   on a 41-mer. *Fix:* divide by `shape[0]`. The thresholds were calibrated with the current
   code (benchmark: loose removes 2.1 %), so rerun the benchmark scores before changing the
   levels; the change only raises scores of large peptides.

### Controls
9. **A control replicate whose K = 1 fit failed is averaged into the control with no flag**
   (`controls.py:515-548`; `fit/optimise.py:325-333` gives a failed measurement the placeholder
   `n_raw = 0, logit_p = 0`, mean 0.3 n, with `fitted(1)` True). CONFIRMED (FD replicates 3.0
   with nll inf and 8.0 give mfd 5.5, no flag). Rare (every restart non-finite). *Fix:*
   `usable &= np.isfinite(fit.fits[1].nll)` with a logged count; consider the same for the
   labelled time course.

### Analysis tables
10. **NaN control times split grouping keys in `populations.csv` and `regions.csv`**
    (`analysis/populations.py:185`, `analysis/compare.py:957`: `float(nan)` keys never meet).
    Each control residue gets three partial population rows (fD_avg only, fD_low only, fD_high
    only) and an empty region row per control point. CONFIRMED (8 rows instead of 4, 3 region
    rows instead of 2); `write_analysis` passes the full residue map, so this reaches the
    shipped tables. *Fix:* key by `time_point(time, role)` as `species.Point` does, or drop
    control rows explicitly before these functions (and decide the rule for the comparison
    functions, which skip controls silently today).
11. **`review_K = 1` is ignored by the species table and `best_set_K`** (design inconsistency,
    not a crash). HISTORY 152 records it as deliberate, but docs/ANALYSIS.md "Ground rules" says
    "the reviewer's K overrides are honoured" and guide population-test.md says such spectra
    "take no part" in the test, while their K = 2 descriptions still fill the K = 2 species rows,
    the lever-rule comparisons and the best_set evidence. *Fix:* either apply `_review_one` in
    `_spectrum_records` as a K ≥ 2 drop (like `screen.one_population`), or reword the ground
    rule.

13. **spectra.csv `narrow_component` reports only the last test step** (`report/tables.py:271`

14. **Series spectra and population panel titles ignore `time_scale = "order"`**
    (`report/series.py:288` `_time_text` calls `format_time` without the scale; three call

15. **Two spectra of one series sharing (time point, replicate) are drawn on top of each other**
    (`report/series.py:169-193`; `plot_populations` `:436-441` overwrites the first's title).

    fall back to the wrapped grid when pairs repeat and warn; or have the readers number
    duplicate reps.
16. **uptake.csv pools rank-1 means across spectra fitted at different K** (`report/tables.py:253-262`,
    key (data_id, point, rank)): a K = 1 mean and a K = 2 low-population mean average into one
    row with n_replicates 3. CONFIRMED. Common once each spectrum has its own K. Whether
    intended is open (question 2). *Fix if not:* group by (data_id, point, K, rank) with a `K`
    column.
17. **series.csv and the controls overview call an uncorrected series "measured"**
    (`report/tables.py:318`; `overview.py:118` counts it in "both measured"). CONFIRMED. *Fix:*
    `controls = "uncorrected"` when `ctrl.uncorrected[r]`; its own bar in the overview.
18. **Tables and series figures do O(series) work per spectrum in the controls lookup**
    (`report/series.py:301-312` `_control_row` and `_uncorrected` rebuild a set and a dict of
    every row per call; called three times per spectrum from the tables). Measured 1.4 ms per
    call at 3,000 series: about 110 s of pure lookup for a run the size of the intact-peptide
    benchmark. *Fix:* one data_id → row map per Results (cached) and vectorised
    `correct_means`.
19. **Residue comparison and overlay figures clip at 1.05** (`report/compare.py:116`), while fD
    is unclipped above 1 and `max_fD` allows 1.1: points between 1.05 and 1.1 and their error
    bars vanish. PLAUSIBLE on real data (labelled points to 1.13 of FD recorded). *Fix:* top =
    max(1.05, 1.05 × max drawn value + se), as `plot_residue_profile` does.

### Engine
20. **`bin_variances` smooths with zero padding, under-stating the first and last bin's
    variance** (`noise.py:740`, `np.convolve(..., mode="same")`). Spectrum [1000, 300, 50, 5, 0]:
    bin 0's smoothed intensity 433 instead of 650, its sd 3.9 % instead of 5.85 % of itself, its
    weight 2.25× too high. The tallest bin of every undeuterated control and low-deuteration
    spectrum is over-weighted relative to the envelope; consistent across fit, polish, screen,
    bootstrap and null, so no statistic/null asymmetry. CONFIRMED. HISTORY 191's `model_error =
    9` was calibrated with this behaviour; tests/test_noise_controls.py:131 asserts it. *Fix:*
    edge-aware mean (`np.pad(y, 1, mode="edge")` then a valid convolution), then re-check the
    calibration (owner's call, with the per-bin noise still opt-in).
21. **A population-test null with no spread gives p = 0 for any T above the tolerance**
    (`population_test.py:210-211` flat branch, `:319-324`). All 20 draws exactly zero → mean =
    var = 0 → p = 0 for T = 0.01, where the honest floor is about 1/21. CONFIRMED for the
    function; measured on the private bundles: 1 of 26,164 simulated cells on the benchmark
    (with T > 0, so p = 0), 4 of 7,748 on the tutorial (none with T > 0). Rare. *Fix:* treat a
    zero-variance null as untested (or the chi-square(3) fallback) or floor p at 1/(B + 1);
    log a count.
