# Audit of 2026-10-17: findings, decisions and plan

A full code audit and readability review of the package as of commit e3917af (five code
reviewers over the whole package, with the deepest reading of everything changed since the audit
of 2026-10-15 recorded in HISTORY item 78, and two readers of the package as a new user). Every
finding below was verified against the code, and the main ones reproduced. The owner stepped
through each item on 2026-10-17; the decisions are recorded here so the work can be done in later
sessions without re-deriving them. Nothing was changed in the repository during the audit.

Baseline at the time: 905 tests pass, 18 skipped (data and GPU), ruff clean, CI green. No critical
finding. The engine changes since the last audit (recurrence pmf, batched k-means starts, the
multimodality screen) were checked numerically and found correct, and bundles written before each
recent column or table open cleanly with today's readers.

## High: wrong results in a realistic path

1. **`time` in `[[input.runs]]` is never type-checked** (`config.py:389`). `time = false` becomes
   a fixed-time run at 0 s (every scan summed into one undeuterated control), `time = true` a run
   at 1 s, `time = "60 s"` a crash in the CLI summary. The folder formats (SpecExport, HX-Express,
   the Bimodal test set) never reach this path.
   *Decision:* now, validate `time` as a real number of seconds or absent, with an error naming the
   run and the accepted forms. The wider design (control identity by label, unit-carrying times,
   an order-only time scale) is a separate session; see "Design items".
2. **Kint mode with too few controls accepts any positive retention** (`controls.py:353-363,
   426`). The rated series get no floor in anticipation of the theoretical back-exchange test,
   and when that model is not fitted (fewer than `kint_min_series` usable or agreeing controls)
   nothing restores a floor; four peptides with FD at 0.10 D per amide gave a tenfold inflated
   correction. The module docstring already says every series then keeps the d2o fallback.
   *Decision:* when the model is not fitted, apply the d2o floor (half of `d2o_fraction`) to the
   rated series too (`retention_low`, fallback FD). Series the model judged are untouched.
3. **Reruns from stored spectra take the control stamps from the project file, not the stored
   record** (`config.py:339, 625`), while logging those settings as "not used". A differing
   `fulldeut_time` makes every series `fd_missing`; `--spectra` on a project of another format
   leaves `fd_time` unset.
   *Decision:* whenever `spectra` is set, take format and both stamps from the stored record and
   recompute the inherited control times; warn once when the file differs; never refuse.
4. **Unknown errors in the protection fits get the largest weight** (`protection.py:437`;
   peptide fit `:221-236`). NaN standard errors (no bootstrap) are mapped to the 0.01 floor,
   five times the weight of a well-characterised point; a single unknown error in the peptide
   fit makes the whole peptide unweighted with a NaN misfit.
   *Decision:* substitute the median of the known errors of the state (or the peptide); keep the
   0.01 floor for known small errors; all unknown gives an unweighted fit. Fix the ANALYSIS.md
   wording.
5. **Peptides with no finite value still count as members and coverage in the residue protection
   fit** (`protection.py:583-592`): a residue covered only by such a peptide is reported resolved
   with a regulariser-only value.
   *Decision:* skip keys with no finite fD before building the design; log the count; the peptide
   table carries `n_times = 0` for them.
6. **Modified and unmodified forms are fitted as one state in the residue protection fit**
   (`protection.py:564-611`), ignoring `modified_peptides = "separate"` (HISTORY 60, 61).
   *Decision:* apply `separate_modified` before building states; each state takes its rates from
   its own peptides; `"together"` keeps the pooling as an explicit choice.
7. **`compare_protection` with range matching keys the reference by range only**
   (`protection.py:693-705`); two reference species over one range collapse to the last.
   *Decision:* reuse `compare._pairs` (one species per side pairs by range; several pair by
   identical sequence), as `compare_peptides` does.
8. **A RunSet with one folder-format run loses every fragment output silently**
   (`analysis/fragments.py:219`, `report/fragments.py:454-458`).
   *Decision:* skip runs whose reader is not a scan reader (the test the other consumers use);
   once fragment series exist, do not swallow ValueErrors; "needs K = 1" gets its own message.
9. **A carried-over review can name a K the screen skipped; the rewritten bundle then fails in
   every reader** (`run.py:614-628`). This led to a wider decision on what `--overwrite` means;
   see "The overwrite contract".

## Medium

1. **Shared envelopes with three or more conditions** (`envelopes.py:348-359`): only the
   top-count condition forms the core, so conditions that agree with the core but not with each
   other are flagged `poor_envelope` although the shared envelope fits them.
   *Decision:* after fitting the core, re-admit excluded conditions whose own references it
   describes within `max_residual`, and refit once. Also: `n_reference` is the picked-with-signal
   count in shared groups (`:376`); keep the pairwise disagreement in the table when a group falls
   back (`:362-367`).
2. **Tables and figures written by `hxex run` and `resume` ignore the carried review**
   (`cli.py:357-360, 384-387`), so they disagree with `hxex report`.
   *Decision:* build the Results with the carried review, the same rule everywhere.
3. **`false` for table-valued `[analysis]` keys gives a traceback** (`config.py:500-516`).
   *Decision:* apply the false-means-unset helper to every optional table before the merges;
   merges inside the error handler; catch TypeError, ValueError and AttributeError.
4. **`exclude_times` checks the control time against `run.undeut_time`** rather than the
   controls' time (`report/analysis.py:118-121`).
   *Decision:* use the controls' undeuterated time when controls exist, else the reference time.
5. **The closure warning no longer fires for a single run** (`report/fragments.py:483-489`; an
   indentation slip in the RunSet change).
   *Decision:* move it back under `if closures:`; a test asserts the message for a single run.
6. **The envelope stage takes no progress or cancellation hooks** (`run.py:508-512`).
   *Decision:* add both, poll per series, own stage name and share of the progress units.
7. The peptide-level protection fit's unknown-error handling: decided with high item 4.
8. **Non-integer bins** (`mixture.py:213-220`): the fractional path normalises over the integers
   but evaluates at fractional points; unbounded near p = 1. Only direct API use reaches it.
   *Decision:* `Measurements` requires whole-number bins; the fractional path is removed.
9. **The species retention time includes rejected and excluded spectra**
   (`species.py:484-499`). *Decision:* apply the same mask the other columns use.

## The overwrite contract (high item 9, widened)

`--overwrite` began as the guard against writing where a bundle exists. HISTORY 72 made it keep
files the user placed in the bundle directory; HISTORY 78 made it carry the review. The owner
asked for best practice rather than a patch. Three kinds of content live in or beside a results
folder: computed results (reproducible, replaceable), annotations (the review: human work, keyed
by stable ids, to be preserved and validated but never silently dropped or trusted), and the
user's own files (never touched). Decisions:

- `hxex run` on an existing bundle refuses, as now; the message names `--overwrite`,
  `--keep-previous` and a different `output.bundle`.
- `--overwrite` replaces manifest-listed files, keeps user files, and carries the review with a
  `stale` marker on entries whose spectrum was dropped or whose K was not fitted (status and note
  kept, override ignored while stale); one log line with the counts.
- The new manifest gets a provenance block: the path replaced, when, which settings changed, and
  how many review entries were carried and are stale. `hxex info` shows it.
- `--keep-previous` (and `[output] keep_previous = true`) moves the old bundle to `<name>.N`,
  with N always increasing and never reused, together with `<name>_tables` and
  `<name>_figures`; sizes are logged; `hxex info` lists the generations.
- The manifest-listed replacement rule extends to the `_tables` and `_figures` folders, which
  today overwrite without checking.

## Readability

Two reviewers read the package as a new user: one ran the CLI, the templates and the docs, the
other read every public docstring and config class. Decisions:

- **Blockers.** Template `[analysis]` scalars are printed after sub-tables, so uncommenting them
  in place fails: print scalars first. `hxex analyse` on a project without time-0 spectra stops
  with "no peptide was measured at time(s) 0": fall back to `coverage_times = "all"` with a
  warning. Analysis-only project files may omit `project` (the help already says so). `hxex
  check` names the missing files or folder, counts a missing data directory as a problem,
  prints the summary before the problems, and tokenises every peptide (file, line, token, modX
  hint). TOML keys are type-checked where they are read, naming table, key, value and the
  expected form; table errors name the column. README gets a quick start, an inputs section
  (peptide-table columns, control convention), one-line definitions of the five formats, a
  Python example and the CLI route for Thermo files.
- **Units and names.** `ci` is percent and `confidence` a fraction: reject `ci` below 1 with a
  message. `rt_window` is seconds while other retention times are minutes: document now; the
  unit-carrying times of the design session resolve it. `resolution_ppm` is a picking half-width,
  not a resolving power: document now (and see the design note below). `retention_min/max` are
  deuterium retention beside retention-time keys: revisit after the time keys are addressed.
  `fd_time` and `fulldeut_time`: document until the role column removes the stamps. `[run.picker]
  noise` becomes `noise_threshold` with a deprecation alias. `min_population` (three stages),
  `d2o_fraction` (three solvents), `reference` (three meanings) and `min_time` (two clocks) get
  cross-references in every docstring and template line.
- **Work with no decision needed.** Comment every `[run.*]` template line with meaning and unit;
  section comments on their own lines; explain the empty `amide_rules` and `registry` tables and
  the `ION:ALL` syntax. Rewrite the config docstrings as user text (one line per field with unit;
  no owner dates, HISTORY numbers or pyHXExpress asides); fix the package docstring and export
  the entry points. Analysis warnings name TOML keys and list only non-zero counts; `hxex run`
  says where figures went; `hxex check` explains "controls off". Tables: `mean_sd` and `n` of
  the uptake table say they are over replicates; `fallback` and `control_fallback` unified;
  `status` becomes `review_status`; `centroid` defined; the empty N-terminal row flagged; the
  old and new header names listed in HISTORY (no private script reads the renamed columns).
  Figure names drop the literal prefix and the bare `data_id`; the populations page is skipped
  at K = 1.
- **Owner TODO (previously unlisted):** a complete pass to create user-friendly documentation
  and tutorials, a user guide separate from the developer documents.

## Other questions settled

- **Protection factors on back-exchange bundles.** They apply (the protection factor is the same
  ratio in either direction under EX2); only the kinetic model differs. Now: refuse a falling fD
  series with a message. Design item: one two-direction model
  `fD(t) = x + (fD(0) - x) * mean_i exp(-k_i t / P_i)`, with `x` the labelling solvent's D
  fraction, `k_i` from `hxex.kint` for that solvent and direction, and `fD(0)` from a time-zero
  point or the fully deuterated control's retention. At quench pH the factors describe the
  peptide under those conditions.
- **RunSet sample-keyed settings.** Now: lookups try `run:sample`, then `sample`. Design item:
  the run is a variable, not part of a name (below).
- `hxex resume` honours `--figures` and `output.figures` like `run`.
- Reruns from stored spectra: the read's m/z window and margin are recorded, and a rerun whose
  picker window or margin exceeds them warns (points outside the stored cut cannot be
  recovered). Storing uncut scans, at a size cost, is the option if reruns should be fully
  independent of the picker.
- Retention times of fragments: in a kinetics (infusion) run no spectrum carries one, parent
  included; in an LC run fragments take their parent's (the back-exchange happened to the parent
  on the column). A retention-time row whose naming cells are all blank is refused.
- The series retention time for the kint model (median over the series' spectra) is documented
  as work in progress. `ms` stays as milliseconds.

## Design items (each its own session)

1. **Control identity by label, not by numeric stamp.** A `role` column per spectrum (undeut,
   fulldeut or none) set by the readers from their labels and by control words in
   `[[input.runs]]`; controls, references and every report or analysis consumer identify
   controls by role; the time column stays numeric. Removes `undeut_time` and `fulldeut_time`
   from `[input]` and `[run.controls]`, the 1e6 sentinel, the collision warning, the HISTORY 71
   trap and `atol`. Together with it: unit strings for times (`"5 min"`) through the shared
   parser, and `[input] time_scale = "seconds" | "order"` for dummy times (plots by index,
   decay and protection analyses refuse). The open questions (unit forms in the analysis
   `times` lists, control words, mixed time scales, the time a control carries) are settled
   below.
   Scope: about 25 to 30 files, five or six commits, two sessions with review between.
   *Decided (owner, 2026-10-18):* scan-format runs declare a control with an explicit
   `role = "undeut"` or `role = "fulldeut"` key in `[[input.runs]]` (no control words
   in `time`; `time = "undeut"` is an error whose message says to use `role`). A run may
   carry both `time` and `role` (a time point that is also a reference). The folder
   formats set the role from their own tokens (`Non`/`Full`, `undeut`/`TD`), which stay
   as the formats define them. Time units: seconds by default; the shared parser's units
   (`ms`, `s`, `sec`, `m`, `min`, `h` and their long forms) are accepted wherever a time
   is written as a string, in `[[input.runs]]`, `[analysis]` lists (`times`,
   `exclude_times`, `coverage_times`) and every other time setting; the loader converts
   to seconds and nothing downstream sees a unit. In the project file `"1.5 min"` is
   90 s: the HX-Express rule that decimals of a time of 1 or more mark replicates stays
   in that reader only, because the format is defined by software outside our control
   and must be read as specified. The time scale is project-wide (`[input] time_scale`,
   seconds by default). A control carries a blank time in tables and plots unless its run
   also has a `time`. Figures label times in a readable unit (`20 h`, not `72000 s`): a
   formatter for labels only; stored values stay in seconds. One explicit override
   remains for promoting a time point to a control: `fulldeut_at` and `undeut_at` in
   `[run.controls]` (folder formats without control files, for example a plateaued 20 h
   point) and in `[analysis.controls]` (an analysis on an existing bundle; the 27 h case).
   The spectra at that time keep their time and gain the role; the match is exact through
   the shared parser (no `atol`), and a time no spectrum has is an error listing the
   times present. "No control of that kind" is the absence of the role (no `false`, no
   sentinel); the fallback settings say what happens then.
   *Session 1 DONE 2026-10-18 (HISTORY 101)*: the role column through readers, picked set,
   measurements, fit and bundle (legacy bundles derive roles from their times), roles in
   `[[input.runs]]`, `undeut_at`/`fulldeut_at`, unit strings in every time setting, the old
   keys refused, consumers grouping by point. *Session 2 DONE 2026-10-18 (HISTORY 102)*:
   `time_scale = "order"` honoured by the plots and analyses, `hxex check`/`info` reporting
   the roles and the time scale, the user guide section's figures, the figure labels
   reviewed (every printed time goes through `format_time`; the tables stay in seconds).
   *Confirmed (owner, 2026-10-18)*: `undeut_marked`/`fulldeut_marked = false` (the spectra at
   `*_at` serve instead of the marked files, not as well): added because the private targeted LC-MS
   example replaces a low-reading fully deuterated run by the 27 h plateau (HISTORY 101).
2. **The run as a variable in the analysis.** `run` and `sample` as separate columns in every
   analysis table; settings keyed by sample with per-run overrides as nested tables
   (`[analysis.labelling.WT]` for all runs, `[analysis.labelling.A.WT]` for run A); the
   `run:sample` label only for display where a sample is in several unmerged runs. Merging is
   unaffected. *DONE 2026-10-18 (HISTORY 103; design in docs/ANALYSIS.md, "The run as a
   variable")*: a merged sample has a blank `run` (its `runs` column lists them); fragment rows
   keep their run with a `merged` flag, as fragment series are never pooled; `reference` and
   `samples` take a sample name (one run of the set) or `run:sample`; `fragments.labels` takes
   a run's own names the same way. The display rule (the prefix only where a sample's name is
   in several runs of the table) and the blank `run` of merged species rows: confirmed by the
   owner, 2026-10-18.
3. **The two-direction protection model** (above). *Decided (owner, 2026-10-18):* `fD(0)`
   is a fitted parameter by default, as the fragment decay fit already does; a measured
   starting state is used only when the user gives a run the fully deuterated role. The
   first usable point stays a user decision (`usable_from`, `min_time`), never an automatic
   choice: early points of kinetics runs have proved unusable, so the earliest or the
   nearest-to-zero point is not a reference. An equilibrium end point of a back-exchange
   run (about 0 D) is a low-D reference, not a fully deuterated control; file-name words
   for such end points are context dependent, so roles are declared per run, not guessed.
   *Peptide level DONE 2026-10-19 (HISTORY 104; docs/ANALYSIS.md, "Direction")*: the
   direction from `initial_fraction` above `d2o_fraction` (no direction setting), `e` over
   `initial_fraction` on the corrected scale, uncorrected back-exchange fitted on the absolute
   scale (owner, 2026-10-19). Left: the residue level (back-exchange states left out with a
   warning), and a real back-exchange dataset with conditions to try it on.
4. **A picking window from the instrument's resolving power.** DONE 2026-10-18 (HISTORY 98):
   `resolving_power` (a value, or `"recorded"` from Thermo raw files) beside `resolution_ppm`,
   FWHM-based, floored at `mass_accuracy_ppm`, capped at half the isotope spacing; the ppm
   window is unchanged (the cap's effect there is to be measured first).
5. **User guide and tutorials** (the owner's TODO).
